Baseline executive verdict

Keep the deterministic evidence and execution core, but make native repository adoption the default product. The framework earns complexity when it binds a result to exact inputs, refuses stale or substituted artifacts, preserves local changes during upgrades, cancels dependent work after failure, and prevents uncertain allocation from becoming a duplicate allocation. These controls have executable tests and, for release and native execution, retained real-run evidence. They are stronger than instructions asking an agent to remember to check its work.

At the baseline, the largest adoption gap was structural. The advertised onboard-adopt route relocates the application and its integration files. Our seven-file Python/Make fixture preserved all original bytes but lost its root GitHub workflow discovery path; it acquired 130 reported created files and contained 146 files outside litai/. A metadata-only adopt-original command exists, but requires an already-authored canonical project. It does not bootstrap a conventional repository into a minimal, contained integration. This conclusion would change with an installed public command that passes the same native-layout, CI-discovery, upgrade and removal fixture. src/literate_ai/cli/operator.py:302; src/literate_ai/adapters/original_project_adoption.py:49; controlled-probe-results.json.

The strongest mission-creep evidence is compulsory conversion and collateral around a native-code change. Root onboarding still calls specifications the authority and generated source disposable; templates spread skills, Flavors, workflows, docs and metadata through the host tree. The framework release policy requires a Google document pair for minor/major cuts. Generation, presentations and courses are legitimate optional products, but their value does not justify forcing their authority or maintenance onto every existing-repository adopter. Reverse this recommendation if controlled pilots show those defaults improve defect detection enough to outweigh onboarding and release costs. SKILL.md:10; literate.release.json:47; docs/decisions/0071-derived-project-litai-directory.md:10.

Multi-day release duration is real; attributing it mainly to inference or CI queueing is not supported. In the observed 1.2 lead-up window, local terminal release-run spans cover 34.02 of 99.77 hours. Python gate spans account for 24.22 hours. The remaining 65.75 hours are unaccounted time, including any editing, reviews, other machines, incomplete runs and idle time; the records cannot partition it. Current-head CI spends most of its longest job in conformance and installed-wheel verification. Repeated qualification and repair are demonstrated costs; approval and inference shares remain unknown. A complete correlated trace could change this ranking.

Do not replace static workers yet. On-demand command provisioning already exists, contrary to treating it as only a proposed direction. It has durable uncertain/ready/registered states and duplicate prevention. It lacks a general lease release/reconciliation protocol; our timeout probe allocated once, refused a duplicate, and could not recover without a validated response. Keep static, local and dynamic acquisition as backends of one execution contract. Live provider reconciliation and expiry tests could overturn the lifecycle gap finding. src/literate_ai/adapters/worker_provisioning.py:189.

Worker contract and pre-CI

Today, explicit worker provision invokes an operator-local versioned command, validates a response and registers an SSH ExecutionWorker in the same catalog used by static workers. Allocation is not automatically part of every job. The request binds request ID, worker ID, target, requirements and parameters; the response binds the request identity and returns a lease ID. The journal is written uncertain before launch. Replaying a registered request is idempotent; an uncertain request refuses automatic relaunch. This is a useful foundation, not a complete ephemeral-worker lifecycle.

The separate retained-allocation inspector checks live allocation identity, workspace prefix and remaining lifetime on POSIX and revokes changed/expired access. It does not supply general lookup-by-request, lease release or a crash reaper for worker provisioning. Registration also does not prove readiness: alignment and observed tool/hardware validation remain necessary. src/literate_ai/adapters/retained_allocation.py:154; src/literate_ai/adapters/execution_dispatch.py:273.

Minimum contractRequired behaviorFailure experiment / residual risk
Acquire(request_id, requirements)Idempotent request across caller restart; return stable lease and attempt identity. Static backend returns an explicitly non-owned lease.Same request must not create a second worker; changed request cannot overwrite an unresolved one.
Observe(request_id or lease_id)Return pending/ready/failed/expired and actual OS/arch/tool/GPU observations with bounded freshness.Allocation succeeds, reply lost: lookup discovers same resource without allocating again.
Execute(job identity, lease, deadline)Bind source tree, dependency/toolchain/environment, command, policy and artifacts; durable job ID and fencing token.Worker disappears: status unknown/failed, no positive receipt; retry uses a new attempt linked to the same logical job.
Cancel(job identity)Terminate owned process tree and confirm remote terminal state or report unknown.Controller disconnect is not remote cancellation. Avoid killing unrelated jobs on static workers.
Collect(job identity)Bounded logs, exact artifact digests, structured test/acceptance results, terminal status.Malformed, truncated or wrong-request output refuses; failed output may be diagnostic but not accepted artifact.
Release(lease) and expiryIdempotent release of owned ephemeral capacity; provider-enforced expiry; bounded reconciliation sweep, never a surprise daemon.Crash between allocation and registry commit, duplicate replies, release failure and expired lease all need fixtures and one authorized real-provider pilot.

Pre-CI earns its cost when it catches a relevant platform/GPU defect before a slow hosted queue, or uses a warm native worker CI cannot provide. It duplicates cost when the same source/tool/test closure is rerun merely because the result came from a different transport. Reuse requires exact source/merge candidate and submodules, declared dependency locks, compiler/SDK/container/image digests, command/environment policy, test inventory and outcome, artifact bytes, trusted signer and current revocation/expiry checks. A successful laptop test is not automatically trusted CI evidence. Keep static workers supported; migrate only acquisition to a common lease abstraction, with opt-in dynamic allocation and explicit cleanup ownership.
