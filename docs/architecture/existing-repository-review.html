Baseline executive verdict

Keep the deterministic evidence and execution core, but make native repository adoption the default product. The framework earns complexity when it binds a result to exact inputs, refuses stale or substituted artifacts, preserves local changes during upgrades, cancels dependent work after failure, and prevents uncertain allocation from becoming a duplicate allocation. These controls have executable tests and, for release and native execution, retained real-run evidence. They are stronger than instructions asking an agent to remember to check its work.

At the baseline, the largest adoption gap was structural. The advertised onboard-adopt route relocates the application and its integration files. Our seven-file Python/Make fixture preserved all original bytes but lost its root GitHub workflow discovery path; it acquired 130 reported created files and contained 146 files outside litai/. A metadata-only adopt-original command exists, but requires an already-authored canonical project. It does not bootstrap a conventional repository into a minimal, contained integration. This conclusion would change with an installed public command that passes the same native-layout, CI-discovery, upgrade and removal fixture. src/literate_ai/cli/operator.py:302; src/literate_ai/adapters/original_project_adoption.py:49; controlled-probe-results.json.

The strongest mission-creep evidence is compulsory conversion and collateral around a native-code change. Root onboarding still calls specifications the authority and generated source disposable; templates spread skills, Flavors, workflows, docs and metadata through the host tree. The framework release policy requires a Google document pair for minor/major cuts. Generation, presentations and courses are legitimate optional products, but their value does not justify forcing their authority or maintenance onto every existing-repository adopter. Reverse this recommendation if controlled pilots show those defaults improve defect detection enough to outweigh onboarding and release costs. Worker contract and pre-CI

Today, explicit worker provision invokes an operator-local versioned command, validates a response and registers an SSH ExecutionWorker in the same catalog used by static workers. Allocation is not automatically part of every job. The request binds request ID, worker ID, target, requirements and parameters; the response binds the request identity and returns a lease ID. The journal is written uncertain before launch. Replaying a registered request is idempotent; an uncertain request refuses automatic relaunch. This is a useful foundation, not a complete ephemeral-worker lifecycle.
